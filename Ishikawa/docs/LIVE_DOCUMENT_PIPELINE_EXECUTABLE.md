# Ishikawa Live Document Pipeline Executable

`ishikawa-produce-artifacts` is the one-shot, repository-neutral executable
behind the live document artifact-stage boundary. It is not a service and it
does not select work by scanning a corpus directory.

For one planner-selected `add`, `revise`, or `reprocess` batch, the executable:

1. validates the exact canonical stage request;
2. rechecks every requested source path and SHA-256 identity;
3. copies only those requested PDFs into a private temporary workspace;
4. runs qualified Poppler extraction and repeatability checks;
5. creates normalized structural units;
6. creates structure-aware chunk candidates;
7. measures tokens and creates Nomic document embeddings; and
8. writes `normalized.json`, `chunks.json`, `embeddings.json`, and the exact
   checksum-bound `stage-result.json` expected by the caller.

The Nomic credential enters through standard input. Only the embedding stage
receives it. It is not placed in the request, command arguments, YAML,
diagnostics, or retained result. The temporary source copies, extraction
evidence, and bounded stage diagnostics are removed before the executable
returns. The caller independently verifies the three returned artifacts and
then removes the enclosing producer workspace after adaptation and retention.

The extraction source manifest is generated by the executable from the
planner request. It records the stable document key, staged filename, byte
count, and source digest. The extraction helper accepts both the historical
fully-synthetic qualification status and the production
`operator_manifest_bound_source` status. It supports a bounded changed-document
batch rather than requiring the original six-document qualification corpus.

Failure is fail-closed and content-free. A failed stage returns only a stable
reason to the parent process. It does not print source paths, document text,
vectors, credentials, or raw dependency exceptions.

Local qualification uses dependency-injected stage execution and the already
accepted live artifacts; it makes no model, database, or target-host call.
The next gate runs this exact executable with native Poppler and the configured
Nomic endpoint on EmceeDanko before connecting it to a publication transaction.
