# Ishikawa v1.3 Change Decision List

## Purpose

This list is the durable authority for the post-v1.2 citation, reconstruction,
and chat-workspace changes. The accepted v1.2 release and its package remain
immutable and available for fallback. Work covered here is a v1.3 candidate
until local and EmceeDanko acceptance are complete.

  rule. Its exception is owned by the versioned sufficiency policy and can be
  reached only through a unique, satisfied, explicit document-identifier
  constraint. A prior answer's ordinary source reference retains the existing
  fail-closed relevance behavior. Diagnostics preserve both the insufficient
  lexical relevance observation and the distinct exact-document sufficiency
  reason so operators can audit why generation was allowed.

- V13-56 keeps exhaustive catalog membership and citation obligations in the
  structured exact PostgreSQL source constraints. Its resolved semantic query
  asks which documents govern the normalized department and which related
  documents they reference, using language present in the authoritative
  Purpose/Scope evidence. It does not repeat every constrained display name or
  every clarification turn. The original bounded conversation still carries
  the operator's topic details to generation. This prevents trusted router
  prose from diluting the unchanged three-of-five citable-relevance
  measurement and changes neither corpus v3 nor V13-47 retrieval ranking.
- The catalog-routing evaluator includes the API's bounded relevance and final
  sufficiency reason codes in its standalone blocker. Future failures can
  therefore distinguish relevance, exact-constraint, reconstruction, and
  context failures without another diagnostic-only execution.
- V13-56 catalog constraints use one deterministic authoritative Purpose/Scope
  citation per selected document. This keeps every department-owned and
  explicitly related document mandatory while avoiding whole-document exact
  expansion in Gemma's prompt. The full cited section remains reconstructed
  from PostgreSQL for operator display.

  first element as text. Applying text functions directly to the JSONB value is
  invalid PostgreSQL and is covered by the native routing regression.
- The initial V13-55 canary incorrectly required `99 TST 2043` page three as
  form evidence for the follow-up question asking which form to complete. The
